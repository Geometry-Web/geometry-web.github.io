# Reference inventory and behavioral measurements

The reference directory is a Windows installation with Geode and packaged game resources. Its files include GeometryDash.exe, libcocos2d.dll, fmod.dll, 4,821 PNGs, 3,833 plists, 216 bitmap fonts, 310 OGGs and 33 MP3s. The inventory includes mod resources. The executable's Windows version fields are empty. Capture the game version and enabled mods on screen before collecting timing measurements.

Commit `2018a6e` contains the editable TypeScript web game. The checked-out root had tracked web files marked deleted. The recovered working copy lives under `web/`. The deployed game's shapes and oscillator sounds are generated by the web implementation. The native executable, mods and packaged resources are reference material.

## What the web simulation currently specifies

| Mechanic | Setup and activation | Observable web behavior |
| --- | --- | --- |
| Cube | Normal speed, level floor, fresh press while grounded | Starts a jump, accelerates toward the floor, then settles at half a block above it. |
| Ship | Ship portal followed by held input | Gains upward velocity during thrust under normal gravity. |
| Orb and pad | Overlap a yellow or pink object | Orb requires a press. Pad supplies an impulse on contact. Blue variants reverse gravity. |
| Portal | Cross a mode, speed or gravity volume | Respective movement setting changes. Test overlapping and consecutive portals separately. |
| Spike | Move through its center with a grounded player | Expanded hazard box and swept center test can end an attempt between positions. |
| Completion | Pass a finish marker | Runtime emits completion. Game presents attempts and collected coins. |

The web coordinate system has 30 units per block. At normal speed its cube uses 340 units/s, a jump velocity of 640 units/s and gravity of 3,200 units/s². The ideal continuous trajectory rises 64 units. Fixed-step integration yields a different discrete apex. These values come from the recovered code. Native measurements and uncertainty intervals remain outstanding.

## Reproducible comparison

1. Make a flat original test level in each editor. Use a marked launch line, one-block markers, a visible floor and normal speed. Record build, device, refresh rate, input device, recording frame rate and enabled mods.
2. Record five runs each with no press, a single jump, a single hazard and a portal followed by a jump. For each run preserve the input frame, apex frame, first landing/contact frame and restart frame. Use the same layout and record any alignment error in block widths.
3. Measure the player's center relative to stationary grid markers to compensate for camera movement. Express distances in blocks and times in seconds using the capture rate. Record frame quantization and the range across trials. Distinguish inferred velocity from the measured displacement.
4. For mode, gravity, speed, orb and pad comparisons, substitute one object at a time at the same marked coordinate. Compare entry position, activation frame, first outgoing displacement, sound onset and resulting mode. Repeat with held input, released input and a restart.
5. For checkpoints, record an uninterrupted run through a collectible and a portal. Die after both and compare the resumed trajectory, object availability, sound phase and progress with the uninterrupted run.
6. Preserve capture identifiers and compare against a fixed-step trace from the corresponding web fixture. Record position, velocity, size, gravity, mode, speed, camera, rotation, input and any event at each tick. Current unit fixtures cover part of this procedure. Native capture and calibrated tolerances are pending.
